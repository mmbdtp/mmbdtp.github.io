## 3. Counting the reads: `seqfu stats`

The directory `reads/lab/` contains the paired-end Illumina reads of the DTP samples (`R1` and `R2` for each sample).

First, explore what is in there (remember the wildcards!):

```bash

```

> How many FASTQ files are there? How many samples does it correspond to?

Have a look at what `seqfu stats` prints for a single file:

```bash
seqfu stats $READS/lab/PID-2959-DTP1-1_S6_R1_001.fastq.gz
seqfu stats --help
```

The default output is already a **tab-separated table** (one row per file, with a header): this is the format we want to save.
The `--nice` option prints a prettier table for the terminal, but it is *not* suitable for saving to a file.

Now create the output directory and the table, **exactly** with this name and location (create a directory if needed):

```text
{firstname}/
└── seqfu-stats/
    └── illumina.tsv
```

```bash
mkdir -p $WORK/seqfu-stats
seqfu stats --basename $READS/lab/*.fastq.gz > $WORK/seqfu-stats/illumina.tsv
```

Notes:

* `--basename` prints the file names without the path, which makes the table easier to read
* `>` **overwrites** the output file: if you need to run the command again, it is fine, but do not use `>>` (it would append a second copy of the table)
* the wildcard `*.fastq.gz` selects only the FASTQ files (and skips for example any `.html` report you might find in the directory)

## 5. Tables

Tables like `illumina.tsv` are the bread and butter of bioinformatics. A few shell commands are enough to reshape them.

### Sorting a table

We want a copy of the table sorted by number of reads (column 2, `#Seq`), **largest first**, saved as `seqfu-stats/illumina.sorted.tsv`.

The header must stay on the first line, so we cannot just sort the whole file: we print the header first, then sort the rest.

```bash
(
  head -n 1 $WORK/seqfu-stats/illumina.tsv
  tail -n +2 $WORK/seqfu-stats/illumina.tsv | sort -t $'\t' -k2,2nr
) > $WORK/seqfu-stats/illumina.sorted.tsv
```

How it works:

* `head -n 1` prints the header only; `tail -n +2` prints everything **from line 2** onwards
* `sort -t $'\t'` says that columns are separated by a *tab*
* `-k2,2nr` sorts using only column 2 (`-k2,2`), as a number (`n`) and in reverse order (`r`), so the biggest comes first
* the parentheses group the two commands, so that **both** outputs go into the same file

Check it:

```bash
head -n 4 $WORK/seqfu-stats/illumina.sorted.tsv | column -t -s $'\t'
```

> What happens if you remove the `n` from `-k2,2nr`? (try it on the screen, without saving the output)

### Selecting columns

The table has 10 columns, but often you only need a few. `cut` selects columns by number (`-f`):

```bash
cut -f 1-3 $WORK/seqfu-stats/illumina.tsv | head -n 3
```

Save the first three columns (file name, number of reads and total bases) in a smaller table, `seqfu-stats/illumina-minimal.tsv`:

```bash
cut -f 1-3 $WORK/seqfu-stats/illumina.tsv > $WORK/seqfu-stats/illumina-minimal.tsv
```

Check that it has the **same number of lines** as the original (`wc -l`) but only **3 columns**:


### Filtering your reads

We will use the same filters as on Day 3, with `fastp`:

- remove adapters (automatic detection)
- discard reads shorter than **100 bp**
- discard reads where **30% or more** of bases have a Phred quality score ≤ 20

The output has to be saved **exactly** like this (this time, **both** pools):

```text
{firstname}/
└── filtered-reads/
    ├── DTP1-N_R1.fastq.gz
    ├── DTP1-N_R2.fastq.gz
    ├── DTP2-N_R1.fastq.gz
    ├── DTP2-N_R2.fastq.gz
    ├── html-reports/
    │   ├── DTP1-N.fastp.html
    │   └── DTP2-N.fastp.html
    └── json/
        ├── DTP1-N.fastp.json
        └── DTP2-N.fastp.json
```

* the filtered reads go in `filtered-reads/`
* the HTML reports (`--html`) go in `filtered-reads/html-reports/`
* the JSON reports (`-j`, or `--json`) go in `filtered-reads/json/`, and their name **must end with** `.fastp.json` (MultiQC will use this to recognise them)

`fastp` does **not** create missing directories, so create them first. Set your number in a variable, then run `fastp` on the first pool:

```bash
mkdir -p $WORK/filtered-reads/html-reports $WORK/filtered-reads/json

N=4                     # <- put YOUR number here
POOL=DTP1
SAMPLE=$POOL-$N
echo $SAMPLE

fastp \
  --in1 $(ls $READS/lab/PID-2959-${SAMPLE}_S*_R1_001.fastq.gz) \
  --in2 $(ls $READS/lab/PID-2959-${SAMPLE}_S*_R2_001.fastq.gz) \
  --out1 $WORK/filtered-reads/${SAMPLE}_R1.fastq.gz \
  --out2 $WORK/filtered-reads/${SAMPLE}_R2.fastq.gz \
  --length_required 100 \
  --unqualified_percent_limit 30 \
  --qualified_quality_phred 20 \
  --thread 4 \
  --html $WORK/filtered-reads/html-reports/${SAMPLE}.fastp.html \
  --json $WORK/filtered-reads/json/${SAMPLE}.fastp.json
```

> The file names contain a sample number that we do not know in advance (`_S7_`, `_S15_`...): the `*` wildcard inside `$(ls ...)` takes care of it. Run the two `ls` commands alone to see what they return.

Now run it **again for the second pool**: change `POOL=DTP1` to `POOL=DTP2` and execute the same commands (use the up arrow, do not retype!). Alternatively, if you are confident, you can wrap the `fastp` command in a loop: `for POOL in DTP1 DTP2; do ... done`.

Check the output:

## 7. Kraken2

[Kraken2](https://github.com/DerrickWood/kraken2) assigns a taxonomic label to each read by comparing it with a database of reference genomes. 
It will tell us **what is in our sample**.

The database is large (about 15 GB), and shared by everybody: we will not copy it, we just tell Kraken2 where it is:

```bash
# This variable will set the default Kraken2 db
export KRAKEN2_DEFAULT_DB=/shared/public/db/kraken2/pluspfp_16gb/2026-06-26/
```

```bash
# Check that the database is there
ls -lh $KRAKEN2_DEFAULT_DB
```

Create a `kraken-reports/` directory, where you will save the **two tsv reports** of your sample (one per pool). The files **must** be named like this:

```text
{firstname}/
└── kraken-reports/
    ├── DTP1-N.tsv
    └── DTP2-N.tsv
```

Run Kraken2 on the **filtered** reads of the first pool (the database is read from `KRAKEN2_DEFAULT_DB`, so you do not need `--db`):

```bash
mkdir -p $WORK/kraken-reports

N=4                     # <- put YOUR number here
POOL=DTP1
SAMPLE=$POOL-$N

kraken2 \
  --paired \
  --threads 4 \
  --memory-mapping \
  --output /dev/null \
  --report $WORK/kraken-reports/${SAMPLE}.tsv \
  $WORK/filtered-reads/${SAMPLE}_R1.fastq.gz \
  $WORK/filtered-reads/${SAMPLE}_R2.fastq.gz
```

Options explained:

* `--paired`: the two files are the `R1` and `R2` of the same reads
* `--report`: the summary table (one line per taxon) that we want to keep
* `--output /dev/null`: we do not need the classification of every single read (that file would be huge): we send it to the "bin"
* `--memory-mapping`: do not load the whole database in memory for each of us (it is faster and lighter when everyone is using it)

Then, as before, repeat for `POOL=DTP2`. Check that you have both reports:

```bash
ls -lh $WORK/kraken-reports/
```

The report is a tab-separated table, with these columns: percentage of reads in this taxon (and below), number of reads in this taxon (and below), number of reads assigned directly to this taxon, rank code, NCBI taxonomy ID, and name.

```bash
head -n 10 $WORK/kraken-reports/DTP1-$N.tsv
```

Rank codes are `U` (unclassified), `R` (root), `D` (domain), `P` (phylum), `C` (class), `O` (order), `F` (family), `G` (genus), `S` (species). Keep only the **species** and show the top 5:

```bash
awk -F '\t' '$4 == "S"' $WORK/kraken-reports/DTP1-$N.tsv | sort -t $'\t' -k1,1nr | head -n 5
```
