## 4. Read statistics with `seqfu stats`

```bash
mkdir -p seqfu-stats

seqfu stats --basename /shared/team/2026_training/week2/reads/lab/PID-2959-DTP1-4_S*_R*_001.fastq.gz /shared/team/2026_training/week2/reads/lab/PID-2959-DTP2-4_S*_R*_001.fastq.gz > seqfu-stats/illumina.tsv
```

`--basename` prints only the file name. `>` writes the output to the file (and
replaces it if it already exists). Inspect the result:

```bash
ls -lh seqfu-stats
cat seqfu-stats/illumina.tsv
```

The table has a header and one line per file. Columns: `File`, `#Seq`,
`Total bp`, `Avg`, `N50`, `N75`, `N90`, `auN`, `Min`, `Max`.

:pencil: **Notebook**:

> 1. How many reads are in each file? Do `R1` and `R2` have the same number?
> 2. Which pool has more reads? What is the typical read length?

## 5. Filtering with `fastp`

`fastp` removes adapters and low-quality reads. With no extra options it uses
its default filters, which is enough today. Create the output directories:

```bash
mkdir -p filtered-reads/html-reports filtered-reads/json
```

Run it on **DTP1**:

```bash
fastp \
  --in1 /shared/team/2026_training/week2/reads/lab/PID-2959-DTP1-4_S*_R1_001.fastq.gz \
  --in2 /shared/team/2026_training/week2/reads/lab/PID-2959-DTP1-4_S*_R2_001.fastq.gz \
  --out1 filtered-reads/DTP1-4_R1.fastq.gz \
  --out2 filtered-reads/DTP1-4_R2.fastq.gz \
  --html filtered-reads/html-reports/DTP1-4.fastp.html \
  --json filtered-reads/json/DTP1-4.fastp.json
```

Now copy the command from your notebook and change every `DTP1` to `DTP2`.
Inspect the output:

```bash
ls -lh filtered-reads filtered-reads/html-reports filtered-reads/json
seqfu stats --basename filtered-reads/DTP1-4_R1.fastq.gz filtered-reads/DTP1-4_R2.fastq.gz
seqfu less filtered-reads/DTP1-4_R1.fastq.gz
```

Open `filtered-reads/html-reports/DTP1-4.fastp.html` in JupyterLab and compare
**before** and **after** filtering.

:pencil: **Notebook**:

> 1. How many reads passed? What percentage was discarded?
> 2. Were adapters removed?
> 3. Do `R1` and `R2` still have the same number of reads?

## 6. `kraken2`: what is in the sample?

Kraken2 compares the reads with a shared database of reference genomes.

```bash
mkdir -p kraken-reports

kraken2 \
  --db /shared/public/db/kraken2/pluspfp_16gb/2026-06-26/ \
  --paired \
  --threads 4 \
  --memory-mapping \
  --output /dev/null \
  --report kraken-reports/DTP1-4.tsv \
  filtered-reads/DTP1-4_R1.fastq.gz \
  filtered-reads/DTP1-4_R2.fastq.gz
```

Repeat for **DTP2**, changing `DTP1` to `DTP2`. This can take a few minutes.
`--paired` says that `R1` and `R2` belong together, `--report` is the summary
table, `--output /dev/null` discards the per-read classification, and
`--memory-mapping` shares the database between users.

Inspect the report:

```bash
ls -lh kraken-reports
head -n 20 kraken-reports/DTP1-4.tsv
```

It is sorted by abundance. Column 1 is the percentage of reads, column 2 the
number of reads, column 4 the rank, and the last column the name. Rank `U` means
unclassified, `S` means species.

:pencil: **Notebook**:

> 1. What percentage of reads is unclassified in each pool?
> 2. What is the most abundant species? Do the two pools agree?
> 3. Which organism do you think you sequenced?
